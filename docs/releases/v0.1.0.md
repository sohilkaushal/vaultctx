# v0.1.0 — draft release notes

Status: unpublished. Final release commit, artifact checksums, license, and
private security-reporting route remain to be confirmed before publication.

`vaultctx` is a local Vault context switcher for macOS and Linux. It manages
connection metadata and delegates Vault operations to the official Vault CLI.
Context selection and local diagnostics do not contact Vault.

## Included in this first release

- Named connection contexts, strict JSON storage, import, list, delete,
  current/previous selection, and destination fingerprints.
- Interactive selection through isolated `fzf`, with a numbered fallback.
- Bash, Zsh, Fish, and PowerShell environment rendering and shell wrappers.
- Explicit clearing of stale Vault connection variables and session-token
  inputs, plus destination-bound opt-ins for token forwarding/helper lookup.
- Managed execution with preserved child exit status and macOS/Linux
  non-interactive process-group cancellation.
- Offline `doctor` diagnostics and a standard-library-only Go runtime.

The release includes the Fish 3.7 empty-value/option-parsing fixes and the
macOS/Linux process-observation and cleanup fixes merged in PR #2.

## Installation

Planned binary archives cover macOS and Linux, each on amd64 and arm64.
Verify an archive against the accompanying `SHA256SUMS`, extract it, and place
`vaultctx` in a directory on your `PATH`. See the included `README.md` for
context creation and shell setup. The official `vault` CLI is required for
Vault operations; `fzf` is optional. Building from source needs Go 1.25+.

Checksums detect changed files; they are not signatures or independent proof
of publisher identity. Signed releases remain a roadmap item.

## Scope and limitations

- This is a security-focused MVP, not an authorization layer or a supported
  Windows release. PowerShell integration does not imply Windows filesystem
  or process hardening.
- Shell activation cannot prevent a later Vault command from reading a global
  token helper. The default `exec` sentinel blocks helper lookup fallback,
  but it does not block helper writes or all provider/auth-method credentials.
- Operator-supplied Vault flags can override the chosen environment.
- macOS extended ACLs are not checked; directory-descriptor hardening remains
  future work. Deliberately daemonized processes are outside group cleanup.
- No remote connectivity checks, keychain helper, or shared context bundles
  are included.

Read `SECURITY.md` before use and report vulnerabilities through the private
route documented there, without including real credentials.
